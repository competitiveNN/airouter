Task: regenerate the fallback chains in ./config.yaml from the freshly fetched
free-model list in /tmp/free-models.json (output of fetch-free-models.py).
Read /tmp/free-models.json and ./config.yaml before editing anything.

Rules:

1. The `providers:` section stays unchanged. Only rewrite the `models:` section.

2. Map the JSON "provider" field to config providers:
   - nvidia-nim      -> nvidia, nvidia2 or nvidia3 (see rule 3)
   - kilocode        -> kilocode
   - opencode        -> opencode
   - ollama-cloud    -> ollama
   - google-ai-studio -> google

  3. Use all three NVIDIA API keys for every NVIDIA model. Any nvidia-nim
     model placed in a chain is emitted as three consecutive entries with
     providers nvidia, nvidia2, nvidia3 (same model id), so a rate-limited key
     falls through to the next key on the same model instead of failing the
     request. Preserve best-first ordering: for each model in score order, emit
     its nvidia / nvidia2 / nvidia3 trio before moving to the next model. No
     nvidia-nim model should ever appear on only one provider.

 4. Order each chain best-first, descending by "intelligence". Skip models whose
    intelligence is null — EXCEPT the two auto-fallback models in rule 6, which
    are always allowed regardless. Note: "intelligence" may come from two sources
    in the JSON — the Artificial Analysis intelligence index, or (when AA has no
    score) a normalized ELO from the arena.ai code leaderboard
    (https://arena.ai/leaderboard/code), exposed as the raw "elo" field. Treat
    "intelligence" as the single sortable score regardless of its source.

5. Profile selection (a model may appear in several profiles when it fits, but
   never twice in the same chain except the nvidia/nvidia2/nvidia3 trio):
   - smart: strongest generalists, intelligence >= 25, any context length.
   - work:  coding workhorses. Same pool as smart plus dedicated code models
     (e.g. cohere/north-mini-code). Drop tiny models (intelligence < 15).
   - fast:  small/cheap models only: intelligence < 25, or ids containing
     flash-lite / lightning / nano / gemma / lfm / laguna-xs. Cap at 10 entries.
   - large: context_length >= 200000 only. Sort by context_length desc, then
     intelligence desc.

6. The LAST entry of EVERY chain is that profile's auto fallback. Count the
   concrete (non-auto) endpoints contributed by kilocode vs opencode in the
   chain:
   - kilocode count strictly greater -> provider `kilocode`, model `kilo-auto/free`
   - otherwise                       -> provider `opencode`, model `big-pickle`
     (ties included, i.e. ties go to kilocode)
   Add a trailing comment with the counts, e.g.:
   `# last: kilocode dominates (5 vs 2)` or `# last: opencode dominates (3 vs 1)`.

  7. Vision capability: for every concrete (non-auto) endpoint you place in a
     chain, look up its source record in /tmp/free-models.json (same provider
     mapping + model id you already use) and read `capabilities.vision`. Emit a
     `vision:` line on that endpoint: `vision: true` when truthy, `vision: false`
     when falsy. This drives capability-aware routing (vision requests are sent
     only to vision-capable models; text-only models are skipped for them). The
     trailing auto-fallback model (kilo-auto/free / big-pickle) is a gateway
     meta-router, so emit `vision: true` for it. For a manually-added model with
     no matching JSON record, keep any existing `vision:` value as-is. Place the
     `vision:` line directly under the `model:` line (the trailing score comment
     stays on the model line), e.g.:
        - provider: nvidia
          model: moonshotai/kimi-k3  # 59.7
          vision: false

  8. Never invent model ids: only use ids present in /tmp/free-models.json.
   Never include: stealth/*, anything matching *content-safety*, or
   x-preview-f-free.

  9. Preserve the existing YAML style: `provider:` / `model:` lines with aligned
    trailing comments carrying the score and notable context size
    (e.g. `# 51.8  131,072 ctx`). When a model also carries an "elo" field in the
    JSON (arena.ai code leaderboard), append it to the comment
    (e.g. `# 51.8 elo=1587  131,072 ctx`). Update the header comment block if the
    distribution rules above changed relative to what it describes.
